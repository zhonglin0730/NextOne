# NextOne Web V0.1 实现基线

> 文档状态：已确认  
> 版本：0.1  
> 日期：2026-07-24  
> 上位文档：`docs/NextOne-总体方案.md`
> 执行计划：`docs/NextOne-V0.1-开发执行计划.md`

## 1. 文档目的

本文档把 Web V0.1 设计稿收敛为可实施的产品基线，解决以下问题：

- 明确哪一批设计稿作为主方案；
- 固定一级信息架构和核心术语；
- 定义收集、执行、决策、每日收尾和每周回顾之间的关系；
- 明确状态、日期和数据安全语义；
- 标注分阶段范围，避免 V0.1 演变为大而全的任务管理器；
- 给开发、测试和后续设计迭代提供共同依据。

NextOne 的核心定位保持不变：

> 一个会主动帮助用户做取舍的个人行动系统。

产品不以“保存更多任务”为目标，而是推动用户对事项做出明确选择：加入今天、开始、拆小、等待、推迟、以后再说或放弃。

## 3. 信息架构

### 3.1 一级导航

Web 一级导航固定为：

```text
项目
今天
收件箱
回顾
看板
设置
```

默认落点是“项目驾驶舱”。项目是个人项目管理的主视角；今天是跨项目的当日执行切片；看板是项目内或全局的辅助视图。

全局区域保留：

- 全局搜索；
- 快速记录；
- 通知入口；
- 用户菜单；
- 同步状态。

### 3.2 二级归属

| 能力 | 归属 |
|---|---|
| 每日收尾 | 今天 |
| 每周回顾 | 回顾 |
| 单项决策 | 回顾或任务上下文 |
| 行动日志 | 回顾 |
| 数据与账户 | 设置 |
| 语言与地区 | 设置 |
| 通知设置 | 设置 |
| 空状态和同步异常 | 全局状态体系 |

以下功能不设置一级入口：

- 标签：任务属性和筛选条件；
- 日志：回顾的完成证据；
- 数据管理：设置子页面；
- 通知：顶部铃铛入口。

以下功能不进入 V0.1：

- 日历；
- 模板；
- 高级统计；
- 专业版升级；
- 团队成员和协作；
- 自定义自动化规则。

## 4. 核心术语

### 4.1 UI 术语

| 推荐用语 | 不再混用 |
|---|---|
| 项目 | 项目驾驶舱、默认首页 |
| 今天 | 今日计划、全部任务首页 |
| 收件箱 | 待澄清箱 |
| 准备就绪 | 接下来作为状态名 |
| 进行中 | 正在做、处理中 |
| 等待中 | 等待 |
| 以后再说 | 暂时隐藏作为用户可见名称 |
| 回顾 | 复盘作为一级导航 |
| 每日收尾 | 每日回顾 |
| 每周回顾 | 每周复盘 |
| 语言与地区 | 区域与语言 |
| 放弃 | 删除任务、从系统移除 |

“接下来”允许作为页面分组标题，但不得作为领域状态名。

### 4.2 内部状态

执行状态：

```text
INBOX
READY
DOING
WAITING
COMPLETED
CANCELED
```

可见性：

```text
ACTIVE
SNOOZED
SOMEDAY
```

“今天做”是 `DailyPlanItem`，不是任务状态。

### 4.3 状态不变量

- `WAITING` 与 `DOING` 互斥；
- 进入 `WAITING` 后释放 DOING 名额；
- `WAITING` 建议记录等待对象、等待原因、开始时间和检查时间；
- “放弃”使用 `CANCELED`，保留历史和日志，不物理删除；
- “重新打开”必须由用户明确触发；
- 拖拽只是状态变更的一种入口，所有操作必须有可访问的按钮替代。

## 5. 页面规格

### 5.1 今天

目标：回答“今天真正要推进什么”。

页面结构：

1. 今日焦点，默认上限 3；
2. 进行中；
3. 之后可做；
4. 需要决定的提示；
5. 每日收尾入口；
6. 快速记录入口。

规则：

- 今日计划和状态分离；
- 未完成事项不自动无限顺延；
- 超过今日上限需要显式确认；
- “加入今天”不等于“立即开始”；
- WAITING 事项只在需要检查时进入今天。

### 5.2 快速记录

默认交互：

- 标题是唯一必填项；
- Enter 保存到收件箱；
- 高级信息默认折叠；
- 系统可识别时间、时长、领域等候选信息；
- 识别结果以可编辑标签展示；
- 不明确的时间语义不得静默写成截止时间。

“周五上午”等表达必须要求或允许用户确认其语义：

- 安排到某天；
- 截止时间；
- 再看日期。

### 5.3 收件箱

目标：把未经判断的输入转成明确行动。

逐项可执行：

- 转为准备就绪；
- 加入今天；
- 立即开始；
- 拆成更小行动；
- 转为等待；
- 设置再看日期；
- 以后再说；
- 放弃。

V0.1 不引入“待澄清”和“可整理”两套额外状态。若后续使用智能识别置信度，只作为推荐信息，不改变任务状态机。

### 5.4 看板

固定展示：

```text
准备就绪
进行中
等待中
以后再说
```

收件箱不作为看板列。

规则：

- DOING 默认上限 3；
- 超限时提示用户先完成、暂停或转为等待；
- 等待卡片突出等待对象、等待时长和下次检查时间；
- SOMEDAY 默认弱化，不制造紧迫感；
- 拖拽和按钮操作产生相同领域事件。

### 5.5 项目

项目列表和详情不展示虚构完成百分比。

项目驾驶舱作为默认首页，优先回答三个问题：哪些项目正在推进、每个项目要取得什么成果、目前有哪些进行中和待开始任务。任务服务于项目推进，而不是脱离项目上下文独立堆积。

项目重点展示：

- 全部进行中任务；
- 排序最前的待开始任务；
- 是否长期未推进；
- 是否存在等待事项；
- 其他待开始任务；
- 本周完成；
- 最近推进记录。

规则：

- 当前执行由全部 DOING 和排序最前的 READY 实时派生，不保存额外焦点字段；
- 完成任务后只展示接续候选，不自动加入今天；
- 没有 READY 或 DOING 任务的活跃项目进入回顾队列；
- 项目详情可以进入仅展示该项目任务的看板；全局看板保留为辅助入口；
- V0.1 不展示成员、负责人或团队协作信息；
- 产品描述统一面向个人，不使用“帮助团队管理”等文案。

### 5.6 回顾中心

回顾中心不是普通统计页，而是待决策问题的聚合入口。

问题类型：

- 长期未推进；
- 等待时间过长；
- 无可执行任务的活跃项目；
- 多次推迟；
- 临近截止；
- 长期占用 DOING；
- 再看日期到达。

页面同时提供：

- 各类型待处理数量；
- 本周期处理进度；
- 继续处理入口；
- 每日收尾入口；
- 引导式每周回顾入口。

回顾中心和基础决策队列进入阶段 1；完整引导式每周回顾进入阶段 2。

### 5.7 单项决策

每项至少提供：

| 动作 | 结果 |
|---|---|
| 加入今天 | 创建今日计划项，任务状态不必改变 |
| 立即开始 | 转为 DOING，并检查 WIP |
| 保持准备就绪 | 保持 READY，更新 `reviewedAt` |
| 拆小 | 创建或改写为更明确的下一步 |
| 设置再看日期 | 设置 `reviewAt`，通常转为 SNOOZED |
| 转为等待 | 转为 WAITING，并补充等待信息 |
| 以后再说 | visibility 转为 SOMEDAY |
| 放弃 | 转为 CANCELED，保留事件和日志 |

界面不得显示 `reviewedAt` 等内部字段名。“保持准备就绪”的说明统一为：

> 暂不安排，记录本次已回顾，之后按规则再次提醒。

“放弃”的说明统一为：

> 移出活跃列表并保留在行动日志中。

### 5.8 每日收尾

每日收尾应在一个页面、数分钟内完成：

1. 确认今天完成的事项；
2. 处理今天未完成的事项；
3. 确认本次主动放弃的事项；
4. 选择明天最重要的三件事。

未完成事项动作：

- 明天继续：加入明天的 DailyPlan；
- 移出今日：保留原任务状态，但不加入明天；
- 转为等待；
- 设置再看日期；
- 以后再说；
- 放弃。

不使用含义相近的“明天继续”和“保持原计划”并列选项。

“哪些不再值得继续”只展示本次收尾过程中被放弃的事项，不提供“添加放弃事项”的独立输入。

### 5.9 每周回顾

采用引导式步骤：

1. 长期未推进；
2. 等待时间过长；
3. 无可执行任务项目；
4. 多次推迟；
5. 截止风险与本周总结。

要求：

- 支持保存并退出；
- 支持上一步和下一步；
- 明确显示总数、已处理数和剩余数；
- “保持准备就绪”更新 `reviewedAt`；
- “再看”统一显示为“设置再看日期”；
- 完成后生成 ReviewSession 和 ReviewItem；
- 跳过是合法选择，但记录跳过事件用于验证产品规则。

### 5.10 通知

通知中心不成为第二个收件箱。

允许的可操作通知：

- 临近截止；
- 等待事项到检查时间；
- 再看日期到达；
- 每日收尾提醒；
- 每周回顾提醒；
- 同步失败；
- 同步冲突。

普通任务字段变化不产生通知。用户可以按类型关闭提醒，并配置免打扰时段。

通知中心在阶段 2 实施，阶段 1 只保留入口位置和本地提醒能力的技术接口。

### 5.11 行动日志

日志来源于不可变业务事件，至少覆盖：

- 完成；
- 主动放弃；
- 转为等待；
- 重新打开；
- WIP 超限确认；
- 回顾决策。

日志属于回顾中心的完成证据，不设置一级导航。V0.1 优先支持按日期、领域和项目筛选，不建设复杂统计仪表盘。

### 5.12 设置与数据

设置分组：

- 通用规则；
- 语言与地区；
- 通知；
- 外观；
- 同步；
- 数据与账户。

数据操作要求：

- 导出支持 JSON，后续支持 Markdown；
- 导入流程为解析、预览、版本检查、创建恢复点、选择合并或覆盖、最终确认；
- 清除本地副本必须明确说明仍可从云端重新同步；
- 删除账户和云端数据与清理本地数据严格分离；
- 覆盖导入、删除账户等高风险动作需要二次确认；
- V0.1 不展示容量套餐和专业版升级。

## 6. 日期与回顾语义

| 字段 | 含义 |
|---|---|
| `deadlineAt` | 错过会产生现实后果 |
| `reviewAt` | 到达后重新考虑 |
| `reviewedAt` | 最近一次明确处理或确认继续保留 |
| `waitingSince` | 开始等待的时间 |
| `completedAt` | 实际完成时间 |
| `canceledAt` | 明确放弃时间 |

停滞判断使用最近一次有意义的用户行为时间，至少考虑：

```text
max(updatedAt, reviewedAt, statusChangedAt)
```

同步产生的纯技术更新时间不得被视为用户推进。

## 7. 国际化与布局约束

V0.1 设置页保留：

- 界面语言；
- 时区；
- 日期格式；
- 每周起始日；
- 12/24 小时制。

实现要求：

- 所有系统文案通过翻译 key 获取；
- 领域枚举和数据库不保存中文显示值；
- 日期、数字、星期和复数通过 locale 格式化；
- 用户内容保持原文，不自动翻译；
- 用户语言和时区分别保存；
- 通知、导出和系统生成内容遵循用户语言；
- 缺失翻译在开发环境报错，生产环境安全回退。

布局要求：

- 用伪本地化验证 30%～50% 文案扩张；
- 决策卡片不得依赖固定四列；
- 操作按钮允许换行或收进更多菜单；
- 德语、英文下不得出现按钮截断；
- 支持浏览器 125% 和 150% 缩放；
- 为 RTL 保留逻辑方向属性和图标镜像能力。

阶段安排：

```text
阶段 1：zh-CN + 伪本地化
阶段 2：en-US
阶段 3：根据需求增加其他语言
```

## 8. 空状态与异常状态

至少覆盖：

- 收件箱为空；
- 暂无项目；
- 离线模式；
- 同步中；
- 同步失败；
- 同步冲突。

要求：

- 空状态提供一个清晰下一步，不堆叠多个按钮；
- 离线状态说明数据仍保存在当前设备；
- 同步失败允许重试和查看待同步项；
- 同步冲突明确展示冲突数量，并引导逐项处理；
- 颜色和图标不能是唯一信息来源；
- 状态文案纳入国际化资源。

## 10. 验收重点

### 核心闭环

- 用户可以只输入标题完成快速记录；
- 用户可以把收件箱事项转换为明确行动；
- 加入今天和立即开始不会被混为同一动作；
- DOING 超限必须显式确认；
- WAITING 不占用 DOING 名额；
- 放弃事项仍能在日志中查询；
- 每日未完成事项不会自动无限顺延；
- 完成一次基础回顾后，刚处理的任务不会立即再次进入停滞队列。

### 数据安全

- 导入前可预览影响范围；
- 覆盖导入前自动创建恢复点；
- 清除本地副本不会误删云端数据；
- 删除账户与清理本地数据是两个独立流程；
- 离线操作恢复联网后不会静默丢失。

### 国际化与可访问性

- 页面通过伪本地化布局检查；
- 英文长文案不遮挡核心操作；
- 键盘可以完成快速记录和核心状态变更；
- 拖拽操作有按钮替代；
- 125% 和 150% 缩放下主要页面可用；
- 低对比度辅助文案达到可读要求。

## 11. 设计待修订清单

进入高保真定稿或开发标注前，应完成：

1. 统一两批设计稿的 Logo、颜色、字号、间距和侧边栏；
2. 删除 V0.1 中的日历、模板、统计、专业版入口和团队文案；
3. 将所有 `reviewedAt` 用户文案替换为自然语言；
4. 将“放弃后从系统移除”改为“保留在日志”；
5. 修正同一任务同时显示 DOING 和 WAITING 的状态冲突；
